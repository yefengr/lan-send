# 局域网快传

浏览器之间直接传输文件。React 页面负责选择设备、确认请求和保存文件；Node.js 服务只负责设备发现、配对与 WebRTC 信令，不接收、存储或中继文件正文。

当前实现首个单文件闭环：选择设备或输入配对码 → 发送请求 → 接收方确认并选择保存位置 → WebRTC 传输 → 校验与保存 → 双方确认完成。页面沿用已确认的[前端设计规范](docs/DESIGN.md)。

## 本地运行

需要 Node.js 24 LTS，以及电脑端 Chromium 内核浏览器。按内核和必要接口检测，不限制 Chrome、Edge 品牌；手机、平板、Safari 和 Firefox 暂不支持。

```sh
npm ci
npm run dev
```

打开 <http://127.0.0.1:5173>。开发服务只监听本机，协调服务使用 `127.0.0.1:8787`。在两个窗口或标签页分别打开页面，可以测试同机传输；每个页面使用独立的临时身份。可先修改设备名，便于辨认。

1. 发送方选择设备，或输入对方页面上的 8 位配对码定位设备。
2. 选择一个文件，点击“发送文件”。
3. 接收方核对设备名、文件名和大小，点击“接收并选择保存位置”。
4. 在系统窗口选择位置，保持双方页面打开，等待最终保存确认。

同公网出口分组和设备名都不能证明身份。配对码只定位设备，不能代替文件接收确认。没有可达的直连路径时，应用会显示失败，不会改走服务器中继。

## 构建与检查

```sh
npm run check
npm test
npm run build
npm start
```

`npm start` 使用构建产物，在 <http://127.0.0.1:8787> 同源提供页面、`/ws` 和 `/healthz`。`/healthz` 只报告服务是否正常，不代表文件直连可达。

测试覆盖共享帧与摘要、真实 HTTP/WebSocket 协调、浏览器核心状态机和关键界面状态规则。浏览器自动化还验证了同机双页面的真实 WebRTC、模块 Worker、真实 OPFS 文件流提交和独立 SHA-256；OPFS 自动化不能替代原生系统保存窗口、真实双电脑或大文件验收。

## 文件保存与结果

文件按 1 MiB 校验块读取，拆成不超过 16 KiB 的消息发送，接收端逐块校验并串行写入。当前采用一个校验块的接收额度，发送缓冲另有限制；不会把整份文件读入内存后再下载。

进度以接收端确认量计算。正文传完后，页面切换到校验、保存或等待确认；没有真实保存百分比时显示阶段和已用时间。只有接收端文件流 `close()` 成功，才确认文件已保存。完成确认丢失时查询已有结果，不重复写入。

取消系统保存窗口会保留当前请求，允许重新选择。取消未完成传输会中止未提交的流；最终提交已经开始时，以实际保存结果为准，不删除已保存文件。结果未确认时应先在接收端核对，避免重复发送。

## 当前边界与后续验证

当前每次传输一个文件，不支持发送文件夹。双方页面需保持打开；当前未实现暂停、连接重建后的续传、刷新恢复、多文件整批目录授权或跨服务重启恢复。

单个 10G 文件是后续必须通过的验收目标，不是已验证能力，也不是大小上限。协议测试覆盖了 4 GiB、10 GiB 偏移编码，但实际 10 GB、10 GiB 的持续传输、内存、慢磁盘和独立文件校验仍需执行。真实双电脑、系统权限与磁盘空间不足也须继续验收。

公网 HTTPS/WSS、可信代理来源识别和 Docker 镜像在后续阶段完成。当前默认仅供本机开发和验收，不应将普通 HTTP 局域网地址当作完整的双电脑部署方案；浏览器保存接口需要安全上下文。

## 配置

默认无需配置。可参考 `.env.example` 在项目根目录创建 `.env`；该文件已被 Git 忽略。开发与构建后运行都会读取它。

| 变量 | 默认与用途 |
| --- | --- |
| `HOST` | `127.0.0.1`，默认只监听本机 |
| `PORT` | `8787`，协调服务端口；当前开发代理固定指向 8787，开发时保留默认值 |
| `PUBLIC_ORIGIN` | 留空时仅允许精确的本机开发和服务 Origin；部署时由 HTTPS 入口配置 |
| `STUN_URLS` | 留空，不使用公共 STUN；需要时填逗号分隔的 `stun:` / `stuns:` 地址，不接受 TURN |

当前不信任转发来源头。出现转发头或使用非本机 Origin 时，自动发现会保守隔离，仍可通过配对码定位设备；不得直接信任任意 `X-Forwarded-For` 来恢复分组。生产代理策略需在部署阶段落实。

服务状态只保存在内存中，无数据库和文件上传接口。常规日志不记录文件名、文件正文、配对码或完整信令。

## 项目结构

- `apps/web`：React 页面、WebSocket 客户端、WebRTC、分块校验 Worker 和文件保存状态机。
- `apps/server`：同源静态资源、设备发现、临时配对与受限信令。
- `packages/protocol`：共享消息校验、帧格式和完整性校验链。校验链不是常规整文件 SHA-256。
- `docs/DESIGN.md`：前端视觉与呈现规则的权威来源。
- `docs/plans/active/20261117-browser-lan-file-transfer.md`：产品范围、技术方案和后续验收边界。
